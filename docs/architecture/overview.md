# Architecture Overview

## Frontend stack
- React + TypeScript
- Ant Design UI components
- Vite build tooling
- Vite PWA plugin for service worker + offline support
- React Router (`HashRouter`) for GitHub Pages compatibility

## Media caching (PWA)
- Service worker is generated by `vite-plugin-pwa` in `vite.config.ts`.
- Static assets (including memetic icons under `src/assets/memetics`) are precached on build.
- Runtime caching is configured for images to keep small media available offline.
- PWA entry points and icons are listed in `public/` and in the PWA manifest.

## User data persistence
- **LocalStorage** is the primary storage mechanism (no backend).
- Stores and keys:
  - `src/storage/configStore.ts` → Tech configs
  - `src/storage/plantingStore.ts` → Planting configs
  - `src/storage/settingsStore.ts` → Theme preference
- Each store normalizes data on load and writes back via explicit save functions.

## Data collections
- **Memetics**:
  - Source: `src/data/memetics.json`.
  - Mapped and normalized in `src/data/memetics.ts`.
  - Icons under `src/assets/memetics`.
  - Scripts: `scripts/scrape-memetics.mjs`, `scripts/download-memetics-images.mjs` (repo has `scripts/` gitignored).
- **Deviations / creature icons**:
  - Source: `src/data/deviations.json`. Icons under `src/assets/creatures/`.
  - Script: `scripts/download-creature-icons.mjs`; filenames list: `scripts/creature-icon-filenames.json`.
- **Plants**:
  - Source: `src/data/plants.json`.
  - Mapped in `src/data/plants.ts`.

## Migration principles
- Use **versioned LocalStorage keys** to avoid breaking old data.
- Add **normalization/migration** logic in store loaders when schema changes.
- Keep migrations additive when possible (e.g., default missing fields).
- If a breaking change is required:
  - Bump storage key version.
  - Provide a migration path or clean reset with a clear UI notice.

## Routing & base path
- `HashRouter` avoids 404s on static hosts (e.g., GitHub Pages).
- Vite `base` and PWA manifest scope are controlled via `.env` (`VITE_BASE_PATH`).
